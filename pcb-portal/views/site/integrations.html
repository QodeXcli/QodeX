Recommended workflow

Branch, upload, review, merge.

  1. Finish placement and net classes; commit on a branch.
  2. Upload the .kicad_pcb (or the zipped project) in the portal.
  3. Download the routed board into the same path.
  4. Review the diff and the 3D model, run KiCad DRC, merge.
$ git switch -c route/rev-b
$ git add hardware/ && git commit -m "placement frozen for routing"
# upload hardware/controller.kicad_pcb at /portal/new
# … routed board delivered …
$ cp ~/Downloads/controller.kicad_pcb hardware/
$ git diff --stat
 hardware/controller.kicad_pcb | 1843 +++++++++
 1 file changed, 1843 insertions(+)
$ kicad-cli pcb drc hardware/controller.kicad_pcb
Found 0 DRC violations
What to send

File checklist

Required

  • .kicad_pcb with every footprint placed
  • Board outline on Edge.Cuts
  • Net classes for anything non-default

Recommended

  • Zipped project (.kicad_pro, .kicad_sch, .kicad_dru)
  • Stackup defined in Board Setup
  • Locked footprints/tracks you want untouched
  • Notes: impedance targets, currents, length windows
Other tools

Altium, OrCAD, EAGLE?

We focus on KiCad so the round-trip is truly lossless. If you work in another tool, KiCad can import Altium, CADSTAR, EAGLE and Fabmaster boards — import, save as .kicad_pcb and upload. Tell us in the notes and we'll review the import before routing.

3D outputs

Every order includes a GLB you can open in the portal or any glTF viewer. Want to make your own? In KiCad 8/9:

kicad-cli pcb export glb -o board.glb board.kicad_pcb

Then drop it into the 3D Studio.
